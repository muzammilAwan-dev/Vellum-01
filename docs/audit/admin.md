# U1 audit: admin (vellum-64, redo) — fixed in vellum-65

**How it ran:** `ROLE=admin npm run audit` in the sandbox (real Vite app, real fonts Fraunces + Plus Jakarta Sans, Chromium 1243): 10 pages × 6 widths (360, 390, 768, 1024, 1280, 1536) × light + dark = 120 shots, axe-core WCAG 2.2 AA + best practice, Tab walk + ARIA snapshot at 1280. Added this chat: full-length shots of all 12 admin pages (incl. test and teacher audit detail) at 390 / 768 / 1280 in both themes, 15 open states per width/theme (every dialog, validation error, temp password, mobile nav, command palette, privacy preview, password mismatch, empty filter), axe on each open dialog, computed contrast of the switch and inputs, an Escape test on modals. Every shot was reviewed with light and dark side by side.

**Verdict:** Solid base. Dark mode has real parity (own surfaces, softened accents, no inverted look); axe finds **no colour-contrast failures** in either theme on pages or dialogs; no crashes, console errors, sideways page scroll or text under 11 px. The problems are concentrated in a few shared pieces: **the modal shell has no dialog semantics** (screen readers, Escape, focus), **the audit event filters overflow at every width**, **the Accounts table breaks at 1024**, **the off switch is invisible**, and the **two-h1 / name-mismatch** pattern from the top bar repeats on every desktop page. Beyond fixes, the admin home doesn't yet tell the admin what needs doing.

## Status after vellum-65
**All 32 findings fixed except A-31** (dark inputs stay recessed: a written design principle in `index.css`). Also fixed: class cards were `<div onClick>` and unreachable by keyboard (found while fixing A-10), `ModalShell` re-ran its open logic on every keystroke (old `useModalA11y`), focus did not return to the opener when a field autofocused, the palette had no Institution/Profile entries. **Correction:** A-28 — the events page already paged by 50; the fix is the day grouping and bulk-row collapse.

**Re-check (same tools, after):** axe-core 0 violations on all 10 admin pages at 360/1024/1280 in light and dark (was: label-name mismatch on every desktop page, empty table header, heading jump); open dialogs 0; integration suite 1121 ok; ESLint clean; `vite build` ok; smoke: all pages (3 roles × 2 widths), `interact.mjs` 82 ok, `profile-check.mjs` 66 ok. `scripts/ui-audit.mjs`: outline-removed 11→10, div-onclick 15→14, others unchanged.
**Left as is:** the 20 px checkboxes (the label around each is the 44 px target); Tab walk's "focus drops to body once" (the walk's wrap-around through browser chrome, present before); class-card focus ring is drawn on a pseudo-element, which the Tab-walk heuristic can't see (checked by eye).

**What changed, by layer:** shared `PageHeader`/`PageFrame` (breadcrumb links, one h1), `StatTile`/`StatGrid`, `Tabs`/`TabPanel`, `Segmented`, `SearchField`, `Notice`, `Field` errors + `FieldGroup`, `ui/switch`, `Chip` pressed state + tick; `useModalA11y` rewritten (stack, Escape, trap, focus return) and used by `ModalShell` and the phone drawer; admin home rebuilt around "Needs your attention" (`lib/adminHome.js`); Accounts: search + role/status/class filters in the URL, one actions menu, Deactivate instead of Remove; Classes: link cards + menu; class detail: tabs, low-average marker, sort; Institution: sections + side nav, hints, status badge; Audit: shared header, integrity card with a disclosure, linked tiles, filter panel, events grouped by day and bulk action. ## Big ideas (≤ 5)
1. **Admin home = "Needs your attention".** A short, ranked list above the counts: high audit signals (link), privacy policy not reviewed, students without a parent contact (count → filtered Accounts), accounts waiting to change a temporary password, classes without a teacher. Empty state: "All in order" with the last integrity check time. Counts move to a compact strip.
2. **One `DataTable` pattern for admin lists** (Accounts, class roster, audit tests/teachers/events): search, filter chips, row "⋯" menu, responsive cards under `narrow`, pagination, sticky header. Fixes A-03, A-05, A-28, A-29 together and is what the backend lists need anyway.
3. **Shared primitives for the repeated breakages:** `ModalShell` → Base UI Dialog (A-01, A-26), `Tabs` (A-18), `StatTile` (A-12/13/14), `PageHeader` with one title source (A-08, A-15), `Switch`/`Checkbox` tokens (A-04).
4. **Audit as a story, not a log:** on Events, group by day and by bulk action, show the before → after mark inline, link every row to its test/teacher. Teacher audit gets a back link and "compared with other teachers" as a small inline chart instead of a chip.
5. **Institution page as settings sections** (Identity · Contact · Student photos · Privacy policy) with a left mini-nav on desktop, each section saving on its own, and a "draft" badge on the Privacy policy entry until reviewed.
