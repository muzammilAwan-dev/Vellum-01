# U1 audit: teacher (vellum-66) — fixed in vellum-66

**How it ran:** `ROLE=teacher npm run audit` in the sandbox (real Vite app, real fonts, Chromium 1243). The capture covered 20 pages × 6 widths (360, 390, 768, 1024, 1280, 1536) × light + dark = 240 shots. Each page also got axe-core (WCAG 2.2 AA + best practice), the mechanical checks, and a Tab walk + ARIA snapshot at 1280.
**Added this chat:** `tools/audit/extras-teacher.mjs`. It takes **full-length** shots of 22 teacher pages (draft and published test, live and completed results) at 390 / 1024 / 1280 in both themes. It also captures **17 open states** at the same widths:
- dialogs: publish, swap question, add bank question (also after an empty save), new course, new thread, share report;
- parent contact form, command palette, phone nav drawer, Tests row menu;
- confirm Stop test, Grade review by student and manual queue, new-test generate;
- Materials paste and Clusters upload paths.

It also runs axe on each open state and an Escape test on every dialog. The live capture's own scrolled shots (`__s1`) only repeat the first screen, because the page scrolls the document and not an inner box. The full-length shots replace them.
Every shot was reviewed, with light and dark compared at 390, 768 and 1024.

**Verdict:** The teacher side has the richest screens in the product, and dark mode has real parity. Dialogs are in good shape: every dialog opened has `role=dialog`, closes on Escape and passes axe; the one exception is the command palette, which has no accessible name. vellum-65's `useModalA11y` fix carried over.
The problems are elsewhere:
- **Core grading flow:** Grade review rows open only with a mouse.
- **Dead or fake UI:** two dead buttons and two dead pickers on Grade review, and a hard-coded "Live activity" feed on the home page.
- **Phones:** five tables are cut off or one word per line. The question-mix row, the Draft review header and the student header overflow.
- **Forms:** 36 unlabelled fields on Draft review.
- **Clarity:** a published test still looks editable. The admin redesign (shared `PageHeader`, `SearchField`, `StatTile`) never reached the teacher pages: 17 hand-rolled headers in 4 sizes and 2 fonts, 4 hand-rolled search boxes, and two `h1` per desktop page.
- **Tile overload:** rows of four stat tiles fill the first phone screen on 10 of 20 pages.

2. **A grading cockpit for Grade review.** The core teacher job deserves a focused screen:
   - Desktop: a split view, with the answer list (by question by default) on the left and, on the right, the student's answer, the rubric with per-criterion ticks, the AI's mark + confidence + reason, and a marks field.
   - Keyboard: `J/K` next/previous, `A` approve, number keys for marks, `R` reason.
   - Optional **anonymous marking**: hide names to reduce bias, a known good practice.
   - A progress meter.
   - Phone: one answer per screen with Previous/Approve/Next at thumb height.

   Fixes T-01, T-03, T-25 together.
3. **One responsive table pattern** (also admin Big idea 2): `DataTable` with column priorities, sticky header, row "⋯" menu, card layout under `narrow`, focusable scroll region. One change fixes Tests, Question bank, Grade review, Results, student history, Analytics and Live roster (T-05).
4. **The test as one object with a lifecycle.** Today a test lives on four routes (`drafts/:id`, `live`, `results/:id`, `review`) with different headers. 5. **"Prepare" as a guided pipeline + calmer chrome.**
